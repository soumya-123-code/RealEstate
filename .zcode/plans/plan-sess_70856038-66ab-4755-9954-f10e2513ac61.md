# CMS Admin Panel — Wire Up & Make Customer Site Fully Dynamic

## Context

The app has a **complete, production-ready CMS infrastructure** that is entirely unwired:
- **Backend**: 8 content models (HeroBanner, Service, Testimonial, Faq, TeamMember, Partner, BlogPost, Agent), plus WebsitePage/PageSection for layout composition, plus SeoSetting, plus ContactRequest/Lead. All have full CRUD API endpoints with admin auth.
- **Admin UI**: 14 fully-built React components in `routes/admin/cms/` — 7 generic CRUD pages (via `CmsEntityPage` engine + `cmsEntityConfigs.js`), plus custom pages for Analytics, Contacts, Leads, Pages, Page Editor, and SEO. All styled with a consistent 679-line SCSS file.
- **Public API**: A `/cms/homepage` aggregation endpoint, per-entity public GET endpoints, and a `/cms/pages/:key` endpoint for section-level control.
- **Public pages**: HomePage, About, FaqPage, BlogListPage, BlogPostPage already fetch CMS data. But SEO, section-level control, and some bug fixes are missing.

**What's missing**: Zero routes registered in App.jsx. Zero sidebar links in AdminLayout. SEO exists end-to-end but no page uses it. One avatar field bug in About.

---

## Implementation Steps

### Step 1: Wire up CMS admin routes in App.jsx

Add lazy imports for all 14 CMS components and register 14 route entries under the `/admin` children array:

```
/admin/cms/analytics      → AdminAnalytics
/admin/cms/banners        → AdminBanners
/admin/cms/blogs           → AdminBlogs
/admin/cms/contacts        → AdminContacts
/admin/cms/faqs            → AdminFaqs
/admin/cms/leads           → AdminLeads
/admin/cms/pages           → AdminPages
/admin/cms/pages/:key      → AdminPageEditor
/admin/cms/partners        → AdminPartners
/admin/cms/seo             → AdminSeo
/admin/cms/services        → AdminServices
/admin/cms/team            → AdminTeam
/admin/cms/testimonials    → AdminTestimonials
/admin/cms/agents          → AdminAgents
```

### Step 2: Add CMS nav group in AdminLayout sidebar

Add a new collapsible `CONTENT` section to the `NAV` array between `MANAGEMENT` and `SYSTEM`, using the existing `contentOpen` state and `collapsible` pattern that's already built but unused. Add all page titles/subtitles to `PAGE_TITLES`/`PAGE_SUBTITLES` objects. Fix `AdminPageEditor.jsx` line 257 hardcoded back-link from `/admin/pages` → `/admin/cms/pages`.

### Step 3: Create `useSeo` hook

New file `client/src/hooks/useSeo.js`:
- Calls `GET /cms/seo/:page` on mount
- Sets `document.title` to the CMS `metaTitle` (or a sensible default based on route)
- Updates `<meta name="description">`, `<meta name="keywords">`, `<meta property="og:title">`, `<meta property="og:description">`, `<meta property="og:image">`
- Cleans up on unmount
- Fails silently (no toast errors for missing SEO data)

### Step 4: Apply `useSeo` to all public pages

Add `useSeo('home')` to HomePage, `useSeo('about')` to About, `useSeo('contact')` to Contact, `useSeo('properties')` to ListPage, `useSeo('blog')` to BlogListPage, `useSeo('faq')` to FaqPage, etc. This means the admin can set per-page meta titles, descriptions, keywords, and OG images that take effect immediately — no code changes needed.

### Step 5: Fix existing bugs

- **About.jsx line 283**: `member.photo` → `member.avatar` (Prisma schema field is `avatar`, not `photo` — team member photos never display)
- **Footer.jsx**: Remove the dead `/cms/services` fetch (fetched into `services` state but never rendered). The services section is already on the homepage via `/cms/homepage`; the footer doesn't need its own copy.

### Step 6: Verify and test

- Run lint (`npm run lint` in client/)
- Run production build (`npm run build` in client/)
- Test admin panel: navigate to each CMS page, verify data loads, create/edit/delete an entity
- Test public pages: verify CMS data renders, verify SEO meta tags update, verify About page shows team avatars

## What this achieves

After implementation, an admin can:
- **Manage all website content** (banners, services, testimonials, FAQs, team, partners, blog posts, agents) from the admin panel
- **Reorder and toggle page sections** via the Page Editor
- **Set per-page SEO** (meta title, description, keywords, OG image) that applies automatically
- **View contacts and leads** from the contact form
- **View CMS analytics** (content counts, business stats)

The customer-facing website becomes fully dynamic — all visible content originates from the database and can be changed without touching code.
