# Admin-Staff Chat App — Bug Fixes, Hardening & Polish

## Scope
Fix all critical/high bugs, harden the support chat PWA, and polish UX. Changes are **frontend-only** in `admin-staff-chat/` unless the backend needs a minor fix to return `role` in chat list responses.

---

## Phase 1: Critical & High-Priority Bugs

### 1.1 Fix broken login flows (`src/lib/api.ts`, `src/components/auth/login-page.tsx`)
- **Password login broken**: `authApi.login(identifier, password)` sends password as `otp` field. Backend expects `password`. Fix: add a separate `loginWithPassword` method in `api.ts` that sends `{ identifier, password }`, and call it from the login page.
- **Phone OTP broken**: `authApi.verifyOtp(identifier, otp)` always sends phone as `email` field. Fix: detect whether identifier is email or phone and send the correct field name (`email` vs `phone`).
- **Dev OTP display**: In development, parse the `devOtp` from the login response and auto-fill it (or show it) so devs don't need to check the console.

### 1.2 Fix dark mode (`src/app/globals.css`, `src/app/layout.tsx`)
- Add `@custom-variant dark (&:where(.dark, .dark *));` to `globals.css` so class-based dark mode works in Tailwind v4.
- Add a dark/light mode toggle button in the sidebar header.

### 1.3 Fix socket userId type mismatch (`src/context/socket-context.tsx`)
- Backend relays `userId` as a **string** (from JWT), but frontend `Message` type expects a **number**. Parse `data.userId` to a number when constructing the received message: `userId: Number(data.userId)`.
- This fixes the "own message" detection (`msg.userId === currentUser?.id`).

### 1.4 Fix receiver missing role/isActive (backend fix + frontend)
- **Backend**: Update `getChats` in `api/controllers/chat.controller.js` to include `role` and `isActive` in the user select clause for both participants and receiver queries.
- This unblocks the tab filters (Customers / Staff) and role badges in the sidebar and chat view.

### 1.5 Add missing `notification.mp3` (`public/`)
- Add a short notification sound file to `public/notification.mp3`. This fixes the 404 on every incoming message for non-active chats.
- Also register it in the service worker's static assets cache list.

### 1.6 Handle `callBusy` event (`src/context/socket-context.tsx`)
- Add a listener for the `callBusy` socket event. When received, call `cleanupCall()` and show a toast: "User is busy on another call."

### 1.7 Fix call duration always 0 (`src/context/socket-context.tsx`)
- Accept the `duration` parameter in `endCall` and pass it in the socket emit instead of hardcoded `0`.

## Phase 2: UX Polish & Hardening

### 2.1 Add toast notifications (`src/lib/toast.ts`, new file + integrate everywhere)
- Create a simple toast system using Radix UI Toast (already a dependency but never used).
- Show toasts for: API failures (load chats, load messages, send message), login errors, call events (busy, ended, rejected), network disconnection.
- Replace all `console.error` error handling with user-visible toasts.

### 2.2 Fix chat sidebar (`src/components/chat/chat-sidebar.tsx`)
- Remove the redundant 10-second polling (socket already handles real-time updates).
- Add a loading skeleton/spinner while the initial chat list loads.
- Remove the hardcoded green dot on the current user's avatar (or conditionally show it based on actual socket connectivity).

### 2.3 Fix unread badge (`src/components/chat/chat-sidebar.tsx`)
- Change the badge from hardcoded `1` to show a dot indicator (since the backend only provides `hasSeen` boolean, not a count). Use a small colored dot instead of a number.

### 2.4 Fix date separators (`src/components/chat/chat-view.tsx`)
- Add date separators between messages when the date changes. Compare each message's date with the previous message and insert a date header when they differ.

### 2.5 Fix mobile keyboard handling (`src/components/chat/chat-view.tsx`, `src/app/globals.css`)
- Use the Visual Viewport API (`visualViewport`) to adjust the chat layout when the mobile keyboard appears, keeping the input visible.
- Add a scroll-to-bottom behavior when the keyboard opens.

### 2.6 Fix new chat dialog (`src/components/chat/new-chat-dialog.tsx`)
- Replace raw `fetch()` calls with `usersApi.list()` from `api.ts` — make a single call without a role filter (the backend requires admin/staff which is fine for this app), or batch the 3 calls through `usersApi`.

### 2.7 Clean up dead code & fix types
- Remove unused type imports (`CallPayload`, `CallAnswerPayload`, `ICECandidatePayload`) from `store.ts`.
- Remove unused zustand states (`chatsLoading`, `messagesLoading`, `setChatsLoading`, `setMessagesLoading`) from the store since they're never used.
- Fix `ChatParticipant` type: make `id` and `chatId` optional (they're only returned by `getChat`, not `getChats`).
- Fix `LoginResponse` type: rename `roleRedirect` to `redirectTo` to match backend.
